# 软路由时间控制系统实施方案

## 项目概述

将现有的时间控制系统从"每台设备安装客户端"的模式升级为"软路由集中管控"模式，通过在网络层面实施访问控制，实现对所有联网设备的统一管理。

**核心优势:**
- ✅ 无需在每台设备安装客户端软件
- ✅ 天然支持所有联网设备(手机、平板、电脑、智能电视等)
- ✅ 集中管理，配置一次生效全网
- ✅ 更难被绕过(网络层控制)
- ✅ 统一的时间策略执行

### 2.2 时间策略引擎

**核心逻辑:**

```lua
-- /usr/lib/lua/controltime/scheduler.lua

module("controltime.scheduler", package.seeall)

-- 检查当前时间是否在允许时段
function check_time_allowed(device_id)
    local config = get_device_config(device_id)
    local now = os.date("*t")
    local current_hour = now.hour
    local current_min = now.min
    local day_of_week = now.wday  -- 1=周日, 2=周一...
    
    -- 获取当天的配置
    local day_config = config["day_" .. day_of_week]
    if not day_config then
        return false, "未配置该天的时间规则"
    end
    
    -- 检查是否在全局禁用时段
    if is_in_blocked_period(current_hour, current_min, day_config.blocked_periods) then
        return false, "当前处于禁用时段"
    end
    
    -- 检查使用时长是否超限
    local used_minutes = get_today_usage(device_id)
    if used_minutes >= day_config.max_usage_minutes then
        return false, "今日使用时间已耗尽"
    end
    
    return true, "允许使用"
end

-- 获取剩余时间
function get_remaining_time(device_id)
    local config = get_device_config(device_id)
    local day_config = config["day_" .. os.date("%w")]
    local used = get_today_usage(device_id)
    local remaining = day_config.max_usage_minutes - used
    return math.max(0, remaining)
end
```

### 2.3 网络访问控制

**实现方式: iptables规则动态管理**

```bash
#!/bin/bash
# /usr/sbin/controltime-apply-rules.sh

DEVICE_MAC=$1
ACTION=$2  # block/unblock

if [ "$ACTION" = "block" ]; then
    # 阻断该设备的所有外网访问
    iptables -I FORWARD -m mac --mac-source $DEVICE_MAC -j DROP
    # 保留内网访问和DNS查询
    iptables -I FORWARD -m mac --mac-source $DEVICE_MAC -d 192.168.1.0/24 -j ACCEPT
    iptables -I FORWARD -m mac --mac-source $DEVICE_MAC -p udp --dport 53 -j ACCEPT
else
    # 解除限制
    iptables -D FORWARD -m mac --mac-source $DEVICE_MAC -j DROP 2>/dev/null
fi
```

**精细化控制(按应用/域名):**

```bash
# 仅阻止特定域名(如游戏服务器)
iptables -I FORWARD -m mac --mac-source $DEVICE_MAC -d 1.2.3.4 -j DROP

# 通过DNS重定向实现应用屏蔽
echo "address=/game.qq.com/127.0.0.1" >> /etc/dnsmasq.d/block.conf
service dnsmasq restart
```

## 五、关键技术难点

### 5.1 HTTPS流量识别

**问题:** HTTPS加密后无法直接看到URL路径

**解决方案:**
1. **SNI字段提取**
   - TLS握手时的Server Name Indication
   - 可识别访问的域名
   
2. **证书指纹匹配**
   - 建立应用证书指纹库
   
3. **IP地址关联**
   - 维护域名-IP映射表

### 5.2 规则切换延迟

**问题:** iptables规则生效有延迟

**优化方案:**
1. 预加载规则，通过标记启用/禁用
2. 使用nftables替代iptables(更快)
3. 规则批处理，减少系统调用

### 5.3 设备MAC地址伪造

**问题:** 用户可能修改MAC地址绕过限制

**防护措施:**
1. 结合IP+MAC双重验证
2. 802.1X认证(企业级)
3. 行为分析检测异常
4. 家长告知和教育

### 5.4 高性能要求

**问题:** 大量设备时性能下降

**优化方案:**
1. 使用nftables(比iptables快30%)
2. 规则缓存和批量更新
3. 异步日志写入
4. 定期清理过期数据
